- 2026-08-16 (M4) — `mlx_whisper` is spawned with **`HF_HUB_OFFLINE=1`**. Without it, `huggingface_hub` checks the model repo online *before* falling back to the cache; on a host whose IPv6 route is dead that hangs in `SYN_SENT` until the TCP timeout. Observed directly: a transcription pinned at 0% CPU for 6+ minutes having burnt 0.65 s total, with one IPv6 socket open to the HF CDN. The model is already cached and §6.5 says the pipeline runs fully offline, so the online check is pure downside.
- 2026-08-16 (M4) — Spawned with **`PYTHONUNBUFFERED=1`**. Python block-buffers `print()` when stdout is a pipe, so the per-segment progress lines would arrive in ~8 KB bursts (or only at exit) and the bar would sit still and then lurch. Verified both ways.
- 2026-08-16 (M4) — Progress comes from `--verbose True` (the CLI default), which **disables** tqdm's frame-counter bar and instead prints one line per segment on stdout. Those lines are newline-delimited, carry real content, and give a content-position percentage against the `ffprobe` duration — strictly more useful than tqdm's frames, and no carriage-return parsing. **The timestamps in those lines omit the hour below 01:00:00** (`transcribe.py:39` emits the hours marker only `if hours > 0`) while the SRT always includes it (`writers.py:203`, `always_include_hours = True`), so the parser accepts both; a pattern requiring `HH:` would have matched nothing for the first hour of a 73-minute lecture and left the bar dead until it suddenly jumped.
- 2026-08-16 (M4) — Completion is driven by **process exit, not by percentage**, and the percentage is clamped to 100. Whisper stops emitting once speech ends, so the bar would otherwise park short of 100 for the whole silent tail (Lecture 2's last marker is 3708 s of a true 3768.58 s — 60.6 s of it); and because the final window is padded to 30 s a segment can end *past* the container duration (measured 108% on a 60 s clip), which would print as a bug.
- 2026-08-16 (M4) — The SRT is written to a fresh `mkdtemp` under `os.tmpdir()` and removed afterwards — never into `_generated/`, which is git-tracked and would otherwise carry the same content twice. The markdown is written as `.<stem>.md.partial` and **renamed** into place only on success, so an interrupted run leaves *no* file rather than a truncated one that reads as complete (the format has no terminator). Any stale `.partial` is unlinked before each run, because a SIGKILLed server never runs the cleanup and `walk()` hides dotfiles from the UI while git still sees them.
- 2026-08-16 (M4) — The stray-job pre-flight matches the **argv signature** (`mlx_whisper .*--output-format srt`), not the bare word: `pgrep -f mlx_whisper` also matches any shell whose command line merely contains that string (reproduced — it matched an unrelated `bash`), and a false positive here is a 409 the user cannot clear. The in-memory lock alone is not enough because the job runs ~73 minutes and a server restart would drop it while Whisper kept running.
- 2026-08-16 (M4) — Duplicate collapsing is **time-windowed over the last 6 lines (90 s)**, not merely consecutive. §6.5 specifies "consecutive segments with identical text", which describes Lecture 2's single-phrase loop — but Lecture 1 produces an **alternating** loop ("So consumers do make suboptimal decisions." / "They are influenced by moods, by emotions." × 7) that a consecutive-only check cannot see, since no two adjacent lines match. The window is bounded so a genuine callback later in the lecture survives. Comparison is on a normalized key (trimmed, whitespace-collapsed, trailing punctuation stripped, casefolded); the written text keeps its original form.
- 2026-08-16 (M4) — The coverage check triggers on the **missing tail**, not a flat percentage: it warns when more than `max(3% of duration, 60 s)` is unaccounted for. The only benign gap ever measured here is Lecture 2's 60.6 s of trailing silence (1.6%), while the real truncation lost 31 minutes — an earlier flat 95% threshold would have stayed silent about a 2.9-minute cut. The absolute floor stops a short clip's ordinary trailing silence from crying wolf (3% of a 10-minute clip is only 18 s). The asymmetry is deliberate: a false alarm is a note Gregory dismisses, a miss silently poisons every digest and quiz built on the file. Percentage is floored, not rounded, so a 94.9% run cannot print "95% covered" and contradict its own threshold.
- 2026-08-16 (M4) — When `ffprobe` returns no duration the transcript says **"coverage unverified"** rather than staying silent. Silence has to mean exactly one thing: without this, an absent warning would read as "coverage checked, fine" in the one artifact whose entire risk is looking complete when it isn't — and that is the same run whose progress bar is already indeterminate, so both safety nets would be out at once with no visible sign.
- 2026-08-16 (M4) — The transcribe route validates `file` by **membership in the subject's listing** rather than by joining a path. That is containment by construction for a route that execs a subprocess on client input: `walk()` skips dotfiles (`subjects.js:78`) and only emits `Dirent.isFile()` entries (`:84`), which is false for symlinks, so nothing outside the subject dir can appear to be chosen. Do not replace this with a path join.
- 2026-08-16 (layout) — Subject folders moved from the repo root into `subjects/`. The data root was doing two jobs: it held `profile.md` and `.studyroom/` AND was the subject search path, which is why discovery needed a `NOT_SUBJECTS = {docs, app}` exclusion list. `ROOT` now keeps only the data root and `SUBJECTS = <root>/subjects` is the search path, so every directory in there is a subject and the exclusion list is gone. `SUBJECTS` is realpath'd at boot: `subjectDir()` returns real paths, and a rename mixing a real source with a non-real destination would move a subject somewhere else entirely if any parent were a symlink. Moved with `git mv` on the directories, which renames them on disk and so carries the gitignored `.mp4` files along.
- 2026-08-16 (CRUD) — Subject and file CRUD in the app, requested by Gregory ("CRUD operations on the web app so I can add new subjects" / "add/delete/update files … I technically want edit/write so I can write my own notes"). This **supersedes §5's "The app and Claude never modify or delete these"** for the app only — Claude's prohibition in `prompts.js` (CREATE only, only under `_generated/`) is untouched. §5 was rewritten rather than left contradicting the code.
- 2026-08-16 (CRUD) — **Delete is an archive-move, never `rm`.** A subject goes to `.studyroom/archive/subjects/<name>-<stamp>/` as `materials/` + `chats/`; a file goes to `.studyroom/archive/files/<Subject>/<stamp>/<rel>`. One `fs.rename` on the same filesystem, gitignored, restorable by hand — so the strongest version of the old rule survives: no app action can actually destroy a material. Edits are a plain overwrite, since git is already the undo for tracked files. The timestamp is LOCAL, not `toISOString()` (M3: UTC stamps yesterday here after 16:00).
- 2026-08-16 (CRUD) — **Upload is a raw-body `PUT`, not multipart.** The client sends one `fetch(url, {method:"PUT", body: file})` per file and the server pipes `req` to a write stream: no parser, no dependency (§4's "add nothing without a reason"), and a 350 MB lecture never lands in memory — measured, server RSS moved 64 MB → 91 MB for a 244 MB upload, checksums equal both ends. Writes go to a `.<name>.part` dotfile renamed into place on success; `*.part` and `*.partial` were added to `.gitignore` because an aborted upload would otherwise leave a stageable 350 MB partial that `walk()` hides from the UI (and it is exactly the file that blows GitHub's 100 MB limit). `transcribe.js`'s `.partial` had the same hole.
- 2026-08-16 (CRUD) — **The file routes are registered BEFORE `app.use(express.json())`, and this is load-bearing.** `express.json()` consumes and ends the request stream for `application/json`, so a route piping `req` never fires: measured on express 5.2.1, a `.json` upload hung forever with nothing written and a stranded temp, and a 1.1 MB one got `413` from the parser's own limit. `.json` is an editable type here and `fetch(body: File)` takes its Content-Type from `File.type`, so drag-drop hit it exactly. `text/markdown`, `application/pdf`, `text/plain` and `video/mp4` all passed through clean, which is why the earlier "express.json only parses application/json so raw bodies pass untouched" reasoning looked right and was wrong. The PATCH file route takes `jsonBody` explicitly — it genuinely wants a JSON body, so blanket-ahead registration would have left `req.body` undefined.
- 2026-08-16 (CRUD) — **`requireSubject` canonicalizes `:s` against the real directory name.** macOS filesystems are case-insensitive but `fs.realpath` does not correct case, so `/api/subjects/ai201/chats` answered 200 with ZERO chats while `AI201` had two, and `store.js`'s `subjectState()` `??=` would then mint a second, empty bucket for the mis-cased key. Pre-existing, but subject CRUD amplifies it: focus-retargeting would patch the empty bucket and the rename/delete busy-guard would report not-busy, both defeated by nothing but URL case. Every route now takes the canonical name from one place. A consequence: a symlinked subject directory is no longer resolvable, because `findSubject` uses `Dirent.isDirectory()` (false for symlinks) — the listing already excluded those, so listing and resolution now agree instead of disagreeing.
- 2026-08-16 (CRUD) — Write-path containment realpaths the **parent**, not the target: the read route (`/files/:s/*`) realpaths the target, which on a write does not exist yet. The resolved target is rebuilt from the real parent so a symlinked intermediate directory cannot redirect a write, and any path segment starting with `.` is rejected — one rule that kills `..` traversal and dotfiles together (a written dotfile would be invisible in the UI anyway, since `walk()` skips them). Verified: `..` escapes, a `.hidden` target and a write through a symlink to `/tmp` all refused, nothing written outside the subject.
- 2026-08-16 (CRUD) — File rename compares **inodes**, not paths, to detect a name clash: on a case-insensitive filesystem `notes.md` → `Notes.md` stats the same file, and a path-equality check would answer 409 on a legitimate case-only rename. Subject rename gets the same property for free from `findSubject`, whose case-insensitive hit resolving to the subject itself is allowed through.
- 2026-08-16 (CRUD) — Mutating a file 409s only when it is the **exact file being transcribed** (`transcribing` now records its `subject`; it carried only `{file, cancel}` before). Blocking every file mutation in a subject for the ~73 minutes a lecture takes is a worse cure than the disease. Subject rename/archive uses the broader guard, since either would move the running job's cwd.
- 2026-08-16 (CRUD) — A chat's `focus` is validated once at creation and then interpolated into every system prompt, so a focus file that is later renamed or removed would steer the whole chat at something that is not there. Rename re-points it (`retargetFocus`, deliberately not via `updateChat` — renaming a file must not reorder the newest-active-first chat list); the message route re-checks it against the listing it already computes and drops it if gone.
- 2026-08-16 (UI) — Per-file actions live in the preview bar, not on the file rows: one file is selected at a time, the rows are already dense, and the badge-wrap bug is still open there. `.preview-bar` had to become `flex-wrap: wrap` with a `min-width` on the title — with five more buttons the filename collapsed to an ellipsis and the meta line vanished entirely, the same squeeze `.chat-head` hit in M3. - 2026-08-16 (M5) — A deck is detected by **content, not filename**: ≥2 line-anchored `Q:` blocks each carrying a non-empty `A:`. Filename-keying would miss the digest kit's plain `flashcards.md` and any deck written by hand. Line-anchored because a naive `split("Q:")` shatters answers that merely mention the letter (measured: neither deck has a mid-line `Q:`). The **pairing** requirement is the load-bearing half: a bare "≥2 `Q:` lines" gate was measured only against Claude-generated decks that follow `prompts.js`, but the app now lets Gregory write his own notes, and a note jotting `Q:` twice as shorthand for open questions would have been silently replaced by a card list with its body hidden. Real decks are 24/24 and 26/26, so pairing costs nothing. Unpaired cards still *render* with an empty answer — pairing gates detection, not display.
- 2026-08-16 (M5) — `.card-a[hidden] { display: none; }` is **defensive, not currently load-bearing** — stated precisely because the wrong version of this note would mislead. As shipped, neither `.card-a` nor the `prose` class it also carries sets an explicit `display`, so the user agent's own `[hidden]` rule is what hides answers today; deleting the guard would change nothing *right now*. It earns its place as insurance against the edit that has broken this codebase twice: the moment anyone gives either class a `display`, the UA rule loses and every answer renders revealed, leaving the deck inert while looking finished. `.card-a[hidden]` at specificity (0,2,0) beats `.prose` at (0,1,0), so it survives that edit. Five sibling guards exist for the same trap (`style.css:145, 159, 264, 388, 439`). Independent of the guard, the acceptance check must be `getBoundingClientRect().height === 0` on first render — asserting `el.hidden` passes in exactly the broken case, which is how M3 lost a day.
- 2026-08-16 (M5) — Deck-ness cannot live in `syncFileButtons`, which derives from the listing `entry` and `editing` only — a listing row carries no text, so it is unknowable until after the fetch. A module-level `currentDeck` is reset at the top of `renderPreview` and published by the markdown branch. The fetch-failure path needed its own `syncFileButtons(entry)` call: it returns before the one at the end of the function, so the PREVIOUS file's Cards toggle would otherwise sit live above an error message.
- 2026-08-16 (M5) — Questions render with `marked.parseInline`, not `marked.parse`: the latter wraps in `<p>`, and a `<p>` inside a `<button>` is invalid HTML. Both halves go through `sanitize()` like every other insertion — `marked` has no sanitizer and the deck is written by a model.
- 2026-08-16 (M5) — The card count shown is the **parsed** count, never the file header's. `flashcards-eigenvalues-2026-08-15.md` opens with "(22 cards)" and holds 24; the renderer reads 24 and puts the two side by side, which surfaces the known model miscount instead of repeating it.

- 2026-08-16 (polish) — `/favicon.ico` 404'd on every page load, the last console noise in the app. Fixed with `app/public/favicon.svg` + `<link rel="icon" type="image/svg+xml">` in both pages, rather than an inline data URI: SVG is a TEXT file, so it stays greppable and editable and adds no binary asset either way, `express.static` already serves `app/public/`, and one file beats two copies of an 800-character data URI that must be kept in sync. - 2026-08-16 (fix) — `getCache` refuses to mint a bucket for a chat that is not in `chats`, returning a throwaway instead. It used to `??=` one for ANY key including `null`, so a message typed with no chat loaded was pushed somewhere invisible and unsendable, and the repaint that followed wiped the failure banner out of `#chat-log`. Membership is the test, **not `id == null`**: the id can be non-null while resolving to nothing — `deleteChat` filters `chats`, deletes the cache entry, then awaits `newChat()`, which can throw and leave `activeChatId` pointing at a chat that no longer exists. A null check alone left that second door open. For the same reason every guard is keyed on `activeChat()` rather than `activeChatId`, and `deleteChat` now clears `activeChatId` before that await.

- 2026-08-18 (tabs) — **Both new-tab overrides key on `fileType()`, the same classifier the listing uses**, so there is no second extension list to drift. `.md` was served `text/markdown`, which browsers download instead of rendering, and `.py`/`.ts`/`.tex` had no mime entry at all and fell to `octet-stream`; the `markdown` and `text` buckets are now forced to `text/plain; charset=utf-8`. The charset is not decoration — the lecture transcripts are UTF-8 and mojibake without it. `pdf` and `video` are deliberately untouched so they keep their native viewers, and the change is safe in-app because all four client reads of `/files/` use `fetch().text()`, which ignores Content-Type.
- 2026-08-18 (tabs) — **The sandbox is an allowlist over `fileType()`, not a denylist over `.html`.** Opening a file in a tab escapes the `<iframe sandbox>` the in-app preview wraps HTML in: the same document at `localhost:4321/files/…` is same-origin and fully scripted, so it could drive the app's own API. `nameError()` allow-lists no extension and `TYPE_BY_EXT` names no image, archive or XML type, so `.svg` (`image/svg+xml`) and `.xhtml` (`application/xhtml+xml`) — both scriptable top-level documents — land in `other`. `Content-Security-Policy: sandbox` therefore covers `html` **and** `other`, which fails closed for the next unknown extension instead of needing a new entry. Never `allow-scripts allow-same-origin`: that pair defeats the sandbox. If interactive explainers are ever wanted, the upgrade is `allow-scripts` on BOTH surfaces.

In a 260px pane it takes the trailing cell's place while shown rather than competing with it for width.

- 2026-08-18 (cross-OS) — **every OS branch in the server lives in `app/server/platform.js`** (`findExecutable`, `spawnCommand`, `killTree`, `openBrowser`, `quoteWin`). `claude.js`, `transcribe.js` and the launcher are the only places that spawn anything, and none of them names a platform. One file to read, and the POSIX path is byte-for-byte what it was.
- 2026-08-18 (cross-OS) — **`spawnCommand` never passes `shell: true`.** Node applies NO quoting once a shell is involved — it joins `[file, ...args]` with spaces — so `--disallowedTools "Bash Task NotebookEdit"` would arrive at cmd.exe as `--disallowedTools Bash` plus two stray words, i.e. Task and NotebookEdit silently stop being denied and the app's only sandbox quietly stops existing. Demonstrated on this Mac through `/bin/sh`: the same argv element prints `[a b]` without a shell and `[a][b]` with one. A Windows `.cmd`/`.bat` therefore goes through `ComSpec /d /s /c` with a command line we build and quote ourselves (`windowsVerbatimArguments`); `.exe` and every POSIX binary still spawn directly. Node refuses to spawn `.cmd` any other way (EINVAL, the CVE-2024-27980 mitigation), and an npm-installed `claude` — or `npm` itself — is exactly that.
- 2026-08-18 (cross-OS) — **the turn prompt moved from argv to stdin** (`claude -p` reads it there; verified). It keeps arbitrary user text off a command line that cmd.exe would re-parse, and sidesteps the ~32k Windows command-line ceiling. `stdio[0]` is now a pipe with an `error` handler: a child that dies before reading emits EPIPE, and an unhandled EPIPE takes the server down.
- 2026-08-18 (cross-OS) — **`killTree` replaces the bare `process.kill(-pid)`.** That call addresses a process GROUP, so on a child spawned without `detached` it throws ESRCH and kills nothing; the launcher is the first such caller. Off Windows it still kills the group when there is one and falls back to the child; on Windows it is `taskkill /T`, because with a `.cmd` shim the pid we hold is cmd.exe's and the real tool would otherwise orphan.
- 2026-08-18 (cross-OS) — **a second transcription engine.** mlx-whisper is Apple-Silicon-only, so every other OS gets openai-whisper — same `large-v3-turbo` weights, different CLI dialect (underscored flags, no `--output_name`; its writer derives `<stem>.srt`, which is the path we already read back). `STUDYROOM_WHISPER` pins one, `STUDYROOM_WHISPER_MODEL` pins the model, otherwise the first one on PATH wins. Read out of openai-whisper 20250625's own source, so the progress-line and SRT parsers needed no change at all.
- 2026-08-18 (cross-OS) — **openai-whisper's first-run model download is surfaced as progress and kept OUT of the error tail.** It fetches 1,617,941,637 bytes on first use and tqdm draws that bar on stderr, redrawn with `\r` and never a `\n` — invisible to a line parser, so a first run would sit at 0% for minutes looking hung, the same presentation as the `HF_HUB_OFFLINE` bug above. Worse, it would have poisoned failures: `stderrTail` is 2048 chars and the old report was `split("\n").pop()`, so a bar with no newlines IS one line and the real error would have been both evicted and unreachable.
