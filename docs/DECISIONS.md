# Decisions log

One line per detail the design doc (`docs/plans/2026-08-15-studyroom-app-design.md`) left open, per its §0: the builder picks the simplest option consistent with §1 and records it here instead of asking. Append-only, newest at the bottom. Format: `- YYYY-MM-DD (Mx) — decision — why`.

- 2026-08-15 (M0) — Express 5.x (5.2.1 installed, current major); wildcard routes therefore use the named form `/files/:s/*path` and `req.params.path` is an array of segments — no reason to start on the previous major.
- 2026-08-15 (M0) — ES modules (`"type": "module"`), paths via `import.meta.dirname` — matches the doc's `import` samples; `__dirname` doesn't exist in ESM.
- 2026-08-15 (M0) — Subject page URL is `/subjects/<name>` (serves `public/subject.html`); dashboard cards link there. M0 ships a placeholder page; M1 fills it.
- 2026-08-15 (M0) — File-listing entries are `{ path, name, size, mtime, type }` (`mtime` in ms; `type` ∈ pdf|video|markdown|html|text|other by extension) so the UI can pick a preview without re-deriving it. Symlinks are skipped.
- 2026-08-15 (M0) — Dotfiles/dot-directories inside subject folders (e.g. `.DS_Store`) are hidden from listings and counts and are refused (403) under `/files/`.
- 2026-08-15 (M0) — `./start` reuses an already-running server on :4321 (just opens the browser) instead of failing with EADDRINUSE; it does not source nvm — `node` is on PATH in Gregory's terminal.
- 2026-08-15 (M0) — Note for M2: the claude CLI loads `CLAUDE.md` from every parent directory, and both `/Users/gregoryerrl/CLAUDE.md` and `~/.claude/CLAUDE.md` sit above every subject dir, so spawned chats inherit them regardless of this repo (today they only carry git-commit rules — harmless). Keeping the repo root CLAUDE.md-free is still required; at M2, ask a fresh chat what instructions it loaded.
- 2026-08-15 (M1) — Markdown renderer = `marked` v18.0.9 (MIT), vendored once as `app/public/vendor/marked.min.js` (the package's own `lib/marked.umd.js` build) — no runtime CDN, no npm dependency. It has no sanitizer, so `subject.js` strips script-like elements, `on*` handlers and `javascript:`/`data:` URLs from its output before inserting (rendered notes share the app's origin; a prompt-injected artifact must not run code). `.html` files are never inlined — `<iframe sandbox>` only.
- 2026-08-15 (M1) — Split view concretely: the left pane is itself two columns (file list 260px | preview), the right pane is the chat (400px) — so files, preview and chat are all visible at once, and the PDF gets full height. Below 1100px the panes stack. Nothing in §3.2 fixes the inner arrangement of the left pane; this is the simplest reading that keeps a PDF readable beside the chat.
- 2026-08-15 (M1) — Subject page keeps the selected file in the URL (`?file=<relative path>`) so reload / share-with-yourself restores the preview. File rows group by top-level folder only (deeper nesting shows as `sub/dir/name` in the row); for `_generated/` the prefix is stripped from the labels so `transcripts/`, `digest-*/` read as folders — URLs are always built from the untouched relative path.
- 2026-08-15 (M1) — `PORT` env var overrides 4321 (default unchanged; `./start` still uses 4321) so a scratch tree can be served beside the real server for checks.
- 2026-08-15 (M2) — `--include-partial-messages` adopted (verified on claude 2.1.233 this day: `stream_event/content_block_delta` text deltas arrive AND the full `assistant` blocks still follow). Deltas are display-only (`{kind:"delta"}` on the wire); persisted assistant text is always the completed `assistant` text blocks joined with blank lines — the client renders `finalized.join("\n\n") + liveDelta` and pushes each completed block, so the bubble and the JSONL agree byte-for-byte.
- 2026-08-15 (M2) — Not adding `--strict-mcp-config`/`--mcp-config`: Gregory's global MCP servers add no measurable spawn latency (≈3.7 s trivial turn either way); their tools merely appear in the model's tool list (denied under `dontAsk` if called). Revisit if clutter ever matters.
- 2026-08-15 (M2) — `state.json` writes are serialized through one promise chain with a unique temp file per write (parallel turns in different chats all persist session ids); the snapshot is stringified at call time.
- 2026-08-15 (M2) — Chat title defaults to the first message truncated to 40 chars (`…`), renameable inline. Tool activity is stored as `{kind:"tool_use", tool, text}` where `text` is a short label ("Reading mml-book.pdf (pages 40–60)"). Cancel and failures persist any completed text blocks as an assistant line, then an `error` line ("Cancelled." / the CLI's message) — history shows what happened; nothing retries.
- 2026-08-15 (M2) — Client abort is detected on `res` 'close' (not `req` 'close', which fires as soon as the body is read on Node ≥16). Syllabus = any material whose name contains "syllabus" (case-insensitive) → mentioned in the system prompt.
- 2026-08-15 (M2) — Spawned chats run with `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Found during M2 accept #5: Claude Code's auto-memory directory is keyed by the git root (`~/.claude/projects/-Users-gregoryerrl-Studyroom/memory/`), so a "remember this: … ORWELL" in chat A was written there and chat B (fresh session, same subject) read it back — and coding sessions on this repo share the same directory. Independent chats (§3.3) require it off; conversation continuity still comes from `--resume`. The only env var the app adds; still no `ANTHROPIC_*`.
- 2026-08-15 (M2) — Spawn env is scrubbed of parent-harness variables (`CLAUDECODE`, `CLAUDE_CODE_*`, `CLAUDE_*` except `CLAUDE_CONFIG_DIR`) before adding the memory knob: when `./start` runs inside another Claude Code session (as it did during the build), the server would otherwise forward that session's `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS=32000`, etc. into every study chat. From Gregory's own terminal none of these exist; scrubbing makes both launches identical. (Checked: `CLAUDE_CODE_EXECPATH` does not change which CLI version runs — 2.1.233 either way.)
